# Flow AI Studio — Marketing Site

React + TypeScript + Vite static site for Flow AI Studio (`/`, `/privacy`, `/support`, `/terms`).

## How routing works (read this before deploying)

This is a client-side-rendered React app (`react-router-dom`), but `npm run build` also
**prerenders** `/`, `/privacy`, `/support`, and `/terms` to real static HTML files:

```
dist/index.html
dist/privacy/index.html
dist/support/index.html
dist/terms/index.html
dist/404.html
```

Each of these files already contains the full page content in the raw HTML — a crawler or
validator that only does a plain HTTP GET (like the Chrome Web Store's privacy-policy checker)
sees the real content immediately, with zero JavaScript execution required. The same JS bundle
still loads afterwards and hydrates the page, so navigation, the FAQ accordion, the mobile menu,
etc. all stay fully interactive for real visitors.

This is handled by `scripts/prerender.tsx`, which runs after `vite build` and renders each route
through `react-router-dom`'s `StaticRouter`, using the exact same route tree as `src/main.tsx`.

## Develop

```bash
npm install
npm run dev
```

## Build

```bash
npm run build
```

This runs `tsc -b && vite build && tsx --tsconfig scripts/tsconfig.json scripts/prerender.tsx`.
Output goes to `dist/`, including the prerendered route files described above.

## Deploy

**Vercel** — framework preset "Vite" (or "Other"), build command `npm run build`, output
directory `dist`. `vercel.json` sets `cleanUrls: true` so `dist/privacy/index.html` is served at
`/privacy`. No rewrites are needed for `/`, `/privacy`, `/support`, or `/terms` — they're real
files. Verify after deploying:

```bash
curl -I https://your-domain.vercel.app/privacy   # expect HTTP/2 200
```

**Cloudflare Pages** — build command `npm run build`, output directory `dist`. A `_redirects`
file (`/* /index.html 200`) is included as a fallback for any route not covered by prerendering.

**GitHub Pages** — publish the contents of `dist/`. `dist/404.html` is generated by the
prerender step and serves as the SPA/not-found fallback. If you deploy under a subpath (e.g.
`username.github.io/repo`), add a `base` to `vite.config.ts` and a matching `basename` to the
`<BrowserRouter>` in `src/main.tsx`.
